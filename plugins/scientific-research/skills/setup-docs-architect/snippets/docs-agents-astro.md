
## Astro pages
- Commands (run in `{{DOCS_DIR}}/`): `npm install`, `npm run dev` (preview), `npm run build` (outputs to `dist/<page>.html` with CSS inlined, so a single file can be opened directly; fonts and KaTeX CSS come from CDNs, so math and fonts degrade offline)
- `.npmrc` sets `bin-links=false` (for compatibility with file systems that do not support symlinks, e.g. exFAT), so the npm scripts call `node node_modules/astro/bin/astro.mjs` directly; do not change them back to `astro dev`
- New pages go in `src/pages/<name>.astro` (top level only, no subdirectories: the index does not list pages in subdirectories, and the in-page "Docs home" link breaks too), with content wrapped in `DocLayout`; the index lists all pages automatically and groups them by `sections` in `src/pages/index.astro` into "Method design / Plans / Implementation / Results and analysis"; add new pages to the matching section (unregistered pages appear under "Uncategorized"); list text comes from the `title` and `subtitle` of the page's `DocLayout` (both must be plain string attributes without double quotes; use 「」 when quotes are needed)
- Site-wide styles live in `src/layouts/DocLayout.astro`, styled after [Kami](https://github.com/tw93/Kami): parchment background, a single ink-blue accent, warm grays, Noto Serif TC, headings at weight 500 without bold; colors always use CSS variables (`--bg`, `--surface`, `--sand`, `--text`, `--heading`, `--muted`, `--border`, `--accent`, `--note-bg`, `--warn`, `--warn-bg`), never hard-coded color codes; dark mode is decided by the banner's day/night toggle (`<ThemeToggle />`, stored in localStorage) or the system setting
- Shared components (`src/components/`):
  - `<M tex={String.raw`...`} />`: inline math; add `display` for math on its own line, generated by KaTeX at build time
  - `<Note>` / `<Warn>`: note box and warning box
  - `<CodeBlock code={String.raw`...`} />`: code block
- Tables use `<div class="table-wrap"><table>…</table></div>`, with `class="num"` on numeric columns; the table of contents uses `<nav><ol>…</ol></nav>` linking to the `id` of each `h2` / `h3`
- Result data goes in `src/data/*.json`, imported by the page; do not copy numbers by hand
- `.astro` treats `{}` as a JS expression, so LaTeX and code containing `{}` are always passed to components as `String.raw` strings
- When linking to code in the repository, use GitHub links (`{{REPO_URL}}/...`)
